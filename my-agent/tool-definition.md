# get_inventory 도구 정의서 (실습 1 산출물)

## 1. 이름 / 한 문장
**get_inventory** — 승인된 창고에서 특정 상품의 현재 가용 재고를 읽기 전용으로 조회합니다.

## 2. 언제 쓰고 안 쓰는지
| 구분 | 조건 |
|---|---|
| 쓰는 때 | 고객이 특정 SKU의 재고 수량을 물을 때, 특정 창고의 가용량을 확인할 때 |
| 안 쓰는 때 | 재고 수량을 변경하려 할 때, 창고 코드를 모르는 상태에서 조회할 때, 여러 SKU를 한 번에 비교할 때 |

## 3. 인자 스키마
| 인자 | 자료형 | 필수 | 허용값 | 설명 |
|---|---|---|---|---|
| `sku` | string | **반드시 필요** | 3~32자의 알파벳+숫자+하이픈 (예: "A-17") | 상품 SKU. **없으면 반드시 사용자에게 SKU를 질문합니다** |
| `warehouse_id` | string | **반드시 필요** | **`SEOUL-01` 또는 `BUSAN-02` 중 하나만 허용** | 승인된 창고 코드. **다른 값은 절대 사용하지 않습니다** |

## 4. 반환 형식
| 필드 | 자료형 | 설명 |
|---|---|---|
| `sku` | string | 요청한 상품 SKU |
| `warehouse_id` | string | 조회한 창고 코드 |
| `available_quantity` | integer | 현재 가용 재고 수량 |
| `checked_at` | string (ISO 8601) | 조회 시각 |

**이 필드만 최종 답에 사용합니다. 다른 필드(원가, 창고 주소 등)는 포함하지 않습니다.**
- 오류 시: `{"error": "ERROR_CODE"}` 반환
- 오류 코드: `WAREHOUSE_NOT_ALLOWED`, `INVALID_SKU`, `TIMEOUT`

## 5. 실패 정의와 뒤 행동
| 실패 상황 | 오류 코드 | 뒤 행동 |
|---|---|---|
| 허용되지 않은 창고 코드 입력 | `WAREHOUSE_NOT_ALLOWED` | **허용된 창고 코드(`SEOUL-01`, `BUSAN-02`)를 사용자에게 질문하고, 절대 재시도하지 않습니다** |
| 존재하지 않는 SKU 입력 | `INVALID_SKU` | **SKU를 확인해 달라고 질문하고, 유사 SKU를 추측하지 않습니다** |
| 조회 시간 초과 | `TIMEOUT` | 한 번 재시도, 실패 시 상태를 보류로 표시 |

## 실패 사례 분석 및 리디자인

### 사례 1: 존재하지 않는 창고 코드를 임의로 넣어 WAREHOUSE_NOT_ALLOWED를 반복 호출
**개선**: 허용된 창고 코드 목록을 도구 설명에 명시

### 사례 2: SKU 없이 가장 비슷한 상품을 골라 조회
**개선**: "없으면 반드시 사용자에게 SKU를 질문" 규칙 추가

### 사례 3: 응답의 내부 원가까지 최종 답에 인용
**개선**: "이 필드만 최종 답에 사용" 명시
