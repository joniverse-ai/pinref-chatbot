# PinRef — 핀터레스트 레퍼런스 이미지 크롤링 어시스턴트

## 서비스 소개
PinRef는 디자이너, 기획자, 마케터가 핀터레스트에서 레퍼런스 이미지를 검색하고 다운로드할 수 있도록 돕는 챗봇 서비스입니다.

## 설계 결정 요약

### 도구를 3개로 정한 이유
search_pins, download_image, list_categories 세 개로 나눈 것은 각 도구의 책임이 겹치지 않도록 하기 위해서입니다. 검색은 읽기만 하고, 다운로드는 쓰기이므로 권한이 다릅니다. 카테고리는 이미지의 분류 상태를 보여주는 읽기 도구로, 검색이나 다운로드와 기능이 겹치지 않습니다.

### 권한을 나눈 기준
읽기 도구(search_pins, list_categories)는 사람 승인이 필요 없습니다. 쓰기 도구(download_image, 카테고리 생성/삭제)는 모두 사용자 확인 후 실행합니다. 특히 다운로드는 로컬에 파일을 저장하는 동작이므로, 사용자가 "다운로드해줘"라고 말해도 실제 실행 전에 재확인합니다.

### 실패 뒤 행동을 그렇게 정한 근거
RATE_LIMITED는 1회만 재시도하고, 실패 시 보류합니다. 서버에 과도한 요청을 보내지 않기 위해서입니다. DOWNLOAD_FAILED도 1회 재시도 후 보류합니다. 네트워크 일시적 오류일 가능성이 높지만, 반복되면 서버 문제일 수 있으므로 이관합니다.

## 실행하지 않은 것과 이유

### 구현을 미룬 것
1. **실제 핀터레스트 API 연동**: 핀터레스트 공식 API는 비즈니스 계정이 필요하고, 이용약관상 자동화된 크롤링이 제한될 수 있어 설계에만 머물렀습니다
2. **Qdrant RAG 연동**: 실습 2에서 MCP 설정은 완료했지만, 실제 문서 인덱싱과 검색 파이프라인은 구현하지 않았습니다
3. **사용자 인증 시스템**: 현재는 로컬 단일 사용자를 가정했으므로, 다중 사용자 인증은 구현하지 않았습니다

### 다음에 측정할 지점
1. 핀터레스트 API 호출 시 실제로 라이선스 정보가 제대로 반환되는지 확인
2. 다운로드 실패 시 재시도 로직이 제대로 작동하는지 확인
3. 대량 다운로드 시 성능과 안정성 확인
